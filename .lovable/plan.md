## Goal

Replace the hard-coded Chinese / Pinyin / English / Arabic columns with a flexible system where the user picks 2–4 languages, assigns one language per column, and the app auto-translates missing columns with AI (editable and regenerable per word).

## 1. Language set

A built-in catalog of supported languages, each with: code, English name, native name, RTL flag, speech-synthesis locale, and an optional "romanization" companion (e.g. Chinese → Pinyin, Japanese → Romaji, Arabic → transliteration).

Initial set: Chinese (Simplified), Chinese (Traditional), English, Arabic, Spanish, French, German, Italian, Portuguese, Russian, Japanese, Korean, Turkish, Hindi, Urdu, Indonesian, Malay, Vietnamese, Thai, Dutch, Persian, Hebrew, Swedish, Polish.

## 2. Column setup UI

A "Languages" setup panel (opened from the game header, also shown before starting):

```text
Column 1 (MAIN)   Column 2        Column 3        Column 4
[ Chinese  ▾ ]    [ English ▾ ]   [ Arabic  ▾ ]   [ + Add ]
 source of truth   translate       translate       (2–4 total)
```

- The leftmost column is the main/source language; all other columns are translated from it.
- Any column can be removed (minimum 2), reordered is out of scope for v1.
- A per-column "show romanization" toggle appears when the language has one (pinyin under hanzi).
- Existing settings (visibility, mute, font size, shuffle) become per-column instead of the four fixed keys.

## 3. Excel import

The parser stops requiring "Chinese" + "English". Instead:
- It reads every column with a header and tries to map each header to a language in the catalog (by English name, native name, or ISO code).
- Unmapped columns are shown in an import dialog where the user assigns a language (or ignores the column).
- If the file has only one column, that becomes the main language and every other configured column is generated by AI.

## 4. AI translation

A new backend function `translate-vocabulary` (Lovable AI, Gemini Flash) takes the main-language words plus a target language and returns translations in a batch, including romanization when relevant.

- Runs automatically for any configured column that has no data after import.
- Progress indicator while translating; failures shown per row with a retry.
- Results are cached with the vocabulary so re-entering a batch doesn't re-translate.

## 5. Per-word edit and regenerate

On each card (and in a compact "word table" view of the current batch):
- **Edit** — inline text field to fix a translation manually.
- **Regenerate** — re-asks the AI for just that word/language, with an optional short instruction ("more formal", "single word") to steer the retry.
- Edited/regenerated values are persisted so they survive reloads.

## 6. Storage

Vocabulary sets, their column/language config, and per-word overrides are saved in the browser (localStorage) keyed by the loaded file, matching how progress is stored today. No account required.

## Technical notes

- `VocabularyItem` changes from fixed fields (`chinese/pinyin/english/arabic`) to `{ id, values: Record<langCode, string>, romanization: Record<langCode, string>, edited: Record<langCode, boolean> }`.
- `gameLogic.createGameCards` becomes column-driven: it maps over the configured column list rather than four named columns; matching logic stays "all selected cards share a vocabId", with required selections = number of visible columns.
- `GameBoard` and `GameSettings` render columns from an array; the Chinese/Pinyin/English/Arabic-specific branches are deleted.
- Speech uses the language's locale for browser TTS; the existing premium ElevenLabs path keeps working for any language.
- Files touched: `src/utils/languages.ts` (new), `excelParser.ts`, `gameLogic.ts`, `storage.ts`, `GameBoard.tsx`, `GameSettings.tsx`, `Card.tsx`, `VocabularyGame.tsx`, `FileSelector.tsx`, new `ColumnLanguagePicker.tsx` + `WordEditor.tsx`, new edge function `translate-vocabulary`.

This is a large rewrite of the game core; it will be built in one pass but the four-column hard-coding disappears entirely.
